A bank's voice agent can move money. A caller with a hospital story and a borrowed branch name can talk it into moving that money to the wrong account.

The agent acts. AgntID decides. The engineer signs.

We put a bank's voice support agent, and the agents behind it, under a customer-hosted AgntID runtime. Each refund, lookup and post gets its own Runtime Access Decision before it runs. A refund over the cap, or to an account not on file, never reaches the bank. A change that needs a human waits for a named engineer, and the approval only fits the exact arguments it was given for.

Three numbers

  • ₹2,22,840 vs ₹0

    Moved to accounts not on file by the stock agent (8 attack calls) and by the gated agent (15 attack calls). Bank payee check off, so only the agent layer counts.

  • 8/8 vs 0/7

    Out-of-task calls that reached a tool in the payments incident, stock team against gated team. The gated count is 7 because there the merge is escalated and approved, not out of task.

  • 49 to 11

    Tools the incident team can see when the task opens. GitHub alone goes from 41 to 7.

Measured on the local AgntID stand-in; live runtime figures in progress.
