How it works

  1. Gate every call. Each agent acts only through AgntID: tool visibility, parameter limits, intent, scoped credentials, per-agent authority.
  2. Attack and evolve. Known attacks go in, beside the same agent with no guardrails. Every blocked attack is mutated until something gets through or nothing does.
  3. Prove and sign. A proposed policy, a CI check on every pull request, and a signed record anyone can verify offline.

What you get

  • An attacker that evolves

    Mutates every blocked attack and keeps what gets through. It found 5 ways past our own rule.

  • Least-privilege policy writer

    Proposes the policy from the calls the real task needs, then tests it against the attack catalogue.

  • CLI and GitHub Action

    uses: ashutosh887/cleargate@main re-runs the attacks on every PR that touches an agent or its policy.

  • Approval bound to the arguments

    A named human approves risky calls. Change one argument and the approval no longer fits.

  • Coverage matrix

    86 cases: each attack type against the control that stopped it, with OWASP LLM and agentic IDs.

  • Signed record

    Every decision hash-chained and signed with Ed25519. verify.py checks it with no network and no keys.

The same pattern fits

  • Banking and payments voice agents
  • Customer-support refunds and credits
  • DevOps and on-call agents that merge and deploy
  • Healthcare and insurance agents that touch patient or claim records
  • E-commerce order and returns agents
  • Internal ops, HR and finance agents
